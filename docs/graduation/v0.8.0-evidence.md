### 2.1 `hardcoded-env` — candidate `fix`/`warning` → `blocker`

71 findings total (API 36, UI 35). Every finding was manually triaged against the source line.

| Category | Count | Triage | Example |
|----------|-------|--------|---------|
| Working credentials hardcoded in specs | 26 | **Uncontested TP** | `data: { email: 'admin@admin.com', password: 'Admin@123' }` (exchange-config.spec.ts:435) |
| Env var with localhost fallback | 32 | **Contested** | `process.env.URL \|\| 'http://localhost:8000'` (28+ sites, both repos) |
| Intentionally invalid credentials in negative tests | 7 | **Contested** | `password: 'WrongPassword123!'` (auth.login.spec.ts:29), `token: 'invalid-token'` |
| Regex `.replace()` on localhost hostname | 4 | **Contested (likely FP)** | `.replace(/^http:\/\/localhost(?=[:/]\|$)/i, 'http://127.0.0.1')` (security-audit.spec.ts:14) |
| RFC 5737 documentation IP in header-spoof test | 1 | **Contested (likely FP)** | `'X-Forwarded-For': '203.0.113.42'` (rate-limit.spec.ts:42) |
| Absolute Windows path in a helper script matched by `TEST_FILE_RE` | 1 | **Contested (likely FP)** | `filepath = r"C:\Users\..."` (support/fix_dedup_test.py:3) |

**Summary:** 26/71 uncontested TP; 45/71 contested, of which 6 are likely scanner FPs (replace-regex lines, documentation IP, helper-script path). Contract #2 requires **zero uncontested FPs** in a triaged trial for `blocker`; the 6 likely-FP findings would need to be either fixed in the scanner or conceded as TPs by the repo owners before that bar is met. The 32 env-fallback findings are contract-consistent (the literal is still hardcoded) but would gate PRs on a widely used local-default pattern.

### 2.2 `brittle-assert` — candidate `report` → `fix`

Corpus precision is 100% (Section 1). The real-repo trial produced **317 findings** (API 208, UI 109), classified mechanically by where the prose string sits on the assertion line:

| Pattern | Count | Contract reading |
|---------|-------|------------------|
| Prose only in the assertion **message argument** — expected value is numeric/boolean/short token | 279 (88%) | Contract predicate applies to the **expected value**; `expect(status).toBe(200)` is listed as clean. These match only because `proseLiteral()` inspects the first quoted string on the line, which is the message arg in `expect(x, 'should …').toBe(200)`. **Scanner/contract gap.** |
| Imported constant treated as literal | 30 (9%) | Documented shallow provenance (contract: "Imported constants are treated as literals unless allowlisted"). Contract-consistent but noisy. |
| Prose **expected value** (true target) | 8 (3%) | Genuine hits, e.g. `expect(count).toBe('2 selected')`, `expect(texts[0]).toBe('All Challenges')`, `expect(errorData.allowed_symbols[0][0]).toEqual('Not a valid string.')` |

**Summary:** the corpus (which has no message-argument samples) does not cover the dominant real-world pattern. Trial precision against contract intent is roughly 8–38/317 depending on whether imported-constant hits are conceded. Evidence gap for Step B: the corpus should gain message-argument clean samples, and `findBrittleAssertMatches` should scope `proseLiteral` to the expected-value argument before the corpus number is treated as representative.
