================================================================================
GAVEL v0.8.0 — PER-ITEM PROMPTS FOR AI MODEL SESSIONS
================================================================================

WORKFLOW PROTOCOL (read before starting any item):

1. ONE ITEM PER SESSION, ONE MODEL PER ITEM.
   After each item: npm run verify green → commit → next item.

2. TIER-A ITEMS ARE IMPLEMENTATION-ONLY.
   The Tier-A model designs and builds the interface. It does NOT self-review.

3. CROSS-REVIEWS ARE BATCHED, NOT PER-ITEM.
   After all related Tier-A items are committed, a single Tier-R session reviews
   them TOGETHER for cross-item consistency. Batching catches contradictions
   between interfaces that per-item review would miss.

4. THE REVIEWER FLAGS, NEVER FIXES.
   The Tier-R model produces a findings table (approve / request-changes).
   It does NOT edit code, schemas, or fixtures.

5. THE IMPLEMENTER APPLIES FIXES.
   After a cross-review requests changes, the ORIGINAL Tier-A implementer
   applies fixes in a dedicated fix-pass session (same model family as the
   original implementation, fresh session). This preserves review independence
   and keeps full context with the implementer.

6. TIER-B ITEMS ARE INDEPENDENT.
   Tier-B items implement against an approved Tier-A contract. They do not
   get cross-reviewed unless the implementation order explicitly says so.

EXECUTION SEQUENCE FOR v0.8.0:

  Phase 1: Tier-A interface design
    Item #1 → commit → Item #2 → commit → Item #3 → commit

  Phase 2: Batched cross-review
    CR Session 1 (reviews items #1, #2, #3 together)

  Phase 3: Fix pass (if CR requests changes)
    Implementer applies fixes → commit

  Phase 4: Tier-B scanners + fixtures
    Item #4 → commit → Item #5 → commit → Item #6 → commit → Item #7 → commit

  Phase 5: assert-drop (A designs, B implements)
    Item #8a (Tier-A harness design) → commit → Item #8b (Tier-B implementation) → commit

  Phase 6: Enterprise CI surfaces (DoD E1–E2)
    Item #9 → commit  (SARIF recipe + GH Action template finalize; Tier C)

  Phase 7: Graduation review
    Graduation Decisions session (A + R reviews all corpus precision evidence)
    If graduation criteria not met → implementer gathers additional evidence → re-review

Model families in use (July 2026):
  OpenAI:    GPT-5.6 Sol (A), GPT-5.6 Terra (B), GPT-5.6 Luna (C)
